# Query and rendering benchmark execution package

This package contains synthetic inventory-reservation and event-time analytics applications, query/rendering benchmark collectors, independent business-state references, software tests, and the unchanged development-trained feasibility model with its fitting inputs.

The development fit retained the informed query-only action for all 864 decisions. Its joint and query-only development scores were both 579/864. Those measurements came from one UTC date and are not the reserved multi-day evaluation.

Comparative acquisition is gated by an actual seven-artifact frozen release, successful public-runner validation and full qualification, a dedicated repository-restricted workload identity, verified free network capacity, a fixed calendar, and one retained attempt per date. The compact v2 protocol uses twenty main dates and at most two preceding qualification dates. Qualification covers the same sixty-six cells per application as main, including both scales, and is excluded from main estimates. Main collection uses standard public Linux runners, with two explicitly selected CPUs per machine. No paid runners, Actions caches or Actions artifact uploads are configured here. Research output is retained as release assets. Runtime flags and retained run reports determine actual acquisition state.

The manual `network-check` mode of Reserved Main Evaluation is an engineering check before that release. It uses four standard public Linux runners and ordinary tagged nodes, tests two private direct connections, and verifies removal of each job's own node. It requires an explicitly configured network approval and a separately recorded `QRL_NETWORK_EXECUTION_SHA`. It acquires no application or database performance data. The identity's Devices Core Write permission is tailnet-wide; the script's exact own-node checks are application safeguards. This tailnet must remain dedicated to the research check. Full run logs and completed or interrupted role bundles are retained in separate release assets. Qualification and main enable variables remain unset until their actual release is ready.

Ordinary registration is verified through the provider's explicit non-ephemeral, single-use auth-key capabilities, requested with a ten-minute expiry through OIDC. The secret is used from a private temporary file and revoked after registration; only the non-secret acknowledgement is retained. Cleanup checks the exact node identity even after a failed mode check. A recovery option is restricted to the recorded nodes in the retained first failed engineering attempt.

Public Release Preparation is a separate manual workflow. Given an explicit prospective calendar, it constructs the actual profile/context/decision/sample files, keeps the actual model/training bytes unchanged, binds the complete committed measurement source tree, and invokes the real seven-artifact verifier with exact development-fit replay on Linux/Python 3.12.15. Calendar v2 requires twenty consecutive future main dates and one or two qualification dates in the two preceding dates. Historical v1 sixty-date protocol reconstruction remains supported. The five-percentage-point precision goal and material-gain threshold refer to standardized feasibility coverage, with no guarantee of achieved precision or power. Its output is a retained candidate; promotion to a separate artifact commit and source-frozen full qualification remain required. The workflow enables no acquisition flag, starts no application/database and needs no Tailscale identity permission.

Public Browser Startup Check exercises the actual pathname-launched cpuset helper, privilege drop and non-root Chromium process tree using local page content only. It sends no application requests and starts no database or Tailscale node. The helper is explicitly packaged because Python import closure does not discover subprocess paths. Browser installation can finish at different times on fresh runners, so paired setup discovery has a separate bounded fifteen-minute rendezvous; operation, browser-task and measurement-window deadlines are unchanged.

The scheduled acquisition workflow can run qualification on its declared dates when qualification is explicitly enabled. Immutable claims stop an unchanged source from being qualified twice, require a source correction for any next qualification date, and enforce the two-attempt budget. Main mode takes priority only after its separate enable flag is set following a verified full qualification. All failed dates and original source releases remain retained. The retired v1 source and six generated artifacts are preserved at tag reserved-main-v1-frozen-source and in their original preparation/qualification releases; code preparation for a corrected release never overwrites those historical commits or assets.

The author-approved v3 calendar amendment preserves the same campaign and both original failed v2 claims, while allowing exactly one additional full qualification, for a total cap of three. It keeps twenty consecutive main dates and every scientific workload, policy and analysis rule unchanged. The extra qualification date and main block are prospectively frozen, with main beginning at least two UTC days after qualification. Preparation verifies the original live claims; acquisition inspects every dated claim in the campaign so a changed calendar cannot hide a consumed attempt. No fourth attempt is granted. Historical v1/v2 reconstruction remains supported. Both acquisition flags stay off until the corrected actual release is verified; main remains off until complete qualification and independent paired replay pass.

Public Application Replay follows each completed source-frozen acquisition attempt, including failed attempts with a date claim. It verifies provider and member digests, both role identities and exact own-node cleanup, and independently replays the complete paired raw evidence before scoring a main application/day component. Qualification receives an audit report but no main score. The daily report keeps equal application weights when a component is unavailable; it reports descriptive identification bounds without interim confidence intervals or effect-based stopping. Failed application audits and their logs remain retained. These analysis jobs have no Tailscale identity permission.

The original private repository, manuscript, accepted document and private Git history are excluded. `public-package-manifest.json` inventories every copied file by byte length and SHA-256. The package is assembled from an explicit entry-point list and local import closure; it does not copy a working directory or Git history wholesale.

It exports semantic snapshots and content-matched visible paint markers without comparative timing estimates. Software-only test fixtures are synthetic and are not experimental measurements.
